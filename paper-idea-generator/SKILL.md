# 从可研报告到论文选题

输入：一个研究课题 + 一份可行性研究报告（可选：目标期刊、可用时间、数据/算力条件）。

输出：

1. 课题与报告的"约束—能力"对齐；
2. 3-5 个值得研究的方向，含筛选理由与淘汰理由；
3. 每个方向下 2-4 个候选选题；
4. 3-5 个深化 idea，含技术路线、创新点、实验设计、风险与退路；
5. 证据审计：哪些文献、数据集、SOTA 数字已核实；
6. 多维评分、组合建议、90 天验证计划。

核心不是"想点子"，而是"用证据筛掉不成立的点子"。

## 四条硬规则

1. **文献必须真实**：所有引用、数据集、SOTA 数字都要用 `web_search` / `web_fetch` 核实，记录 URL/DOI 与访问日期。不得凭记忆写参考文献，不得编造论文标题、作者、年份或指标。
2. **区分三种事实**：报告事实 / 文献事实 / 你的推断。推断必须显式标注，不能写成已有结论。
3. **论文 idea ≠ 工程交付**：把报告里的研究内容原样复述不是论文选题；必须有可证伪的新问题、新方法、新数据或新评测。
4. **可验证**：每个创新点都要有对应消融实验；没有数据或无法评测的 idea，直接降级或淘汰。

## 输入与假设

- 必需：研究课题（一句话或关键词）、可研报告文件。
- 可选：目标期刊/会议、可用时间、数据权限、算力、作者专长、是否接受中文发表、是否要求结合企业场景。
- 缺信息时先按报告推断并写明假设；只有影响选题方向的缺口才问用户，一次最多 3 个问题。

## 流程

### 1. 读报告，建立"约束—能力"清单

- 用 `scripts/extract_report.py` 提取全文（docx/txt/md；PDF 需有文本层），保留标题层级与表格。
- 提取：项目目标、技术栈、数据来源与类型、业务场景、考核指标、课题划分、已有基础/预研、试点条件、交付物。
- 把用户课题映射到报告章节或课题：它是报告内的子问题、相邻扩展，还是报告外的新方向？
- 列出：项目能提供什么（数据、场景、平台、算力、工程验证）、不能提供什么（标注预算、设备、时间、公开数据许可）。
- 若报告与课题明显不匹配，先说明错位，再给"借用报告数据/场景"的可行路径，不要硬凑。
- 只提取与选题相关的信息，不在本 skill 里复述整份报告；用户需要报告讲解时，另用 `feasibility-report-explainer`。

### 2. 把工程目标转成科学问题

用链条：工程目标 → 观察到的瓶颈 → 现有方法为何不够 → 可证伪的科学问题。

- 差："研究基于深度学习的航拍地物提取。"
- 好："在杆塔—树木强遮挡且训练样本稀缺时，如何利用几何先验降低小目标漏检，并给出可量化的不确定性？"

每个课题至少 1 个科学问题；区分六类缺口：性能、鲁棒性、数据、评测、部署、理论。若提不出科学问题，说明该课题目前更像工程集成，应先补问题定义。

### 3. 文献检索（三轮）

1. **领域扫描**：task + survey/review/benchmark，近 3-5 年，中英文各一轮；找 2-3 篇综述建立地图。
2. **最近邻**：task + method + dataset + application 的组合查询；每个候选方向找 3-5 篇直接相关工作。
3. **查新**：用拟议方法的关键词组合做精确检索，重点看近 6-12 个月 arXiv 和顶会，判断是否已被做过。

- 记录每次查询式、日期、来源；建文献表（格式见 `references/search-and-verify.md`）。
- 找不到直接工作不等于首创；只能写"据检索未见"。

### 4. 生成并筛选方向（3-5 个）

每个方向写：一句话定义、对应报告痛点、文献现状（饱和/空白/争议）、为什么现在、项目独特优势、代表工作、主要风险。

用五问筛选，至少过四问：

- 是真问题吗（有人用、有失败案例）？
- 有缺口吗（现有方法明确不够）？
- 有数据吗（公开或项目内可得）？
- 可验证吗（指标、baseline、消融能落地）？
- 与项目契合吗（数据/场景/平台能复用）？

淘汰"把报告章节换个说法""把方法名当方向""追热点但无数据"的方向。

### 5. 拆选题（每个方向 2-4 个）

选题 = 具体任务 + 数据 + 方法切入点 + 评价方式。

每个选题给：工作标题、一句话 claim、类型（新任务/新方法/新数据基准/新评测/跨域迁移/系统实证）、最小可发表单元（MPU）。

淘汰：6-12 个月做不出 MPU 的、需要不可得数据的、纯工程集成的、创新点只能靠"组合模块"的。

### 6. 深化 3-5 个 idea

按 `references/output-template.md` 的 idea card 写全：标题、claim、问题与 gap（含最近工作表）、科学假设、技术路线、创新点、实验设计、预期结果、风险与退路、资源估算、发表匹配、与报告的关系、伦理合规。

- 技术路线写到"输入→处理→输出"和阶段里程碑，不写空泛的"先训练后优化"。
- 创新点用"主张—机制—证据—消融"四元组；每条创新必须有独立消融。
- 实验至少 2 个强 baseline（含报告现有做法/商用引擎的可比基线），同数据、同划分、同指标。
- 预期结果给区间和判据，不写"达到 SOTA"这种无法兑现的话。
- 每个 idea 动笔前至少完成 2 次针对性检索（最近邻 + 查新）；写完后逐条核实引用，未打开的文献不得标"已核实"。

### 7. 证据审计

逐条列出：文献、数据集、SOTA 数字、标准/规范、工具。

- 状态：已核实（A/B）、仅读摘要、未核实。
- 检查标题/作者/venue/年份/DOI；数据集官方页面（规模、许可、划分）；SOTA 是否同 benchmark、同指标。
- 冲突证据并列呈现；不可用证据对应的 idea 降级。
- 输出"未核实清单"，明确告诉用户哪些结论还不能信。

### 8. 综合评价

- 9 维评分：新颖性、价值、项目契合、数据、可行性、算力、风险、发表匹配、可辩护性。
- 用 `scripts/score_ideas.py` 计算加权分与排序；硬约束一票否决（无数据/无算力/伦理/已被人做过）。
- 给组合建议：稳妥、冲刺、快速各选哪个；排序与依赖；避免多个 idea 共用同一瓶颈。
- 每个 idea 给 90 天最小验证实验和 kill criteria。
- 评分锚点、权重、决策规则见 `references/evaluation.md`。

### 9. 输出

- 开头先给"三个结论"：最推荐、最稳、最高风险高回报。
- 再按模板给全文；引用编号，文末列全；每个 idea 附最近工作表。
- 明确标注三类事实；中文为主，论文标题中英双语。
- 篇幅：完整版 4000-8000 字；用户要"快速版"时给方向表 + 3 个 idea 简卡 + 评分表。

## 质量门槛（交付前逐条检查）

- 每个 idea ≥3 篇直接相关文献，其中 ≥2 篇 A 级；否则标"探索性"。
- 每个创新点都有对应消融和 ≥2 个 baseline。
- 数据计划写到来源、规模、标注方式、许可。
- 不出现"首次/首创"，除非完成穷尽检索；否则用"据检索未见"。
- 评分可复算，总分与排序一致。
- 所有 URL 可访问并记录访问日期；无法访问的标注。
- 联网不可用时，明确写"本次未能联网核实"，并把新颖性/可辩护性结论降为"待核实"。
- 报告指标没有被当成文献 SOTA。

## 资源

- `references/output-template.md`：完整输出结构、idea card、方向表、评分表模板。
- `references/search-and-verify.md`：检索式、证据分级、引用格式、查新与证据审计方法。
- `references/idea-design.md`：缺口类型、选题原型、创新点与实验设计、领域视角。
- `references/evaluation.md`：九维评分锚点、权重、否决规则、组合与发表匹配。
- `scripts/extract_report.py`：docx/txt/md 全文提取，保留标题与表格。
- `scripts/score_ideas.py`：按评分 JSON 计算加权总分、排序与结论。
- `assets/scorecard-template.json`：评分输入模板。
