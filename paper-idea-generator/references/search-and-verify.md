# 检索、查新与证据核实

目标不是"找到几篇看起来相关的论文"，而是建立一张可复核的证据网：哪些工作已经做过、做到什么程度、用什么数据、结论是否可信、你的 idea 与它们的真实差异在哪里。

## 一、检索前：把课题拆成四组关键词

| 组别 | 作用 | 示例（按你的课题替换） |
|---|---|---|
| 任务词 | 确定问题域 | 三维重建、真正射影像、地物要素提取、点云分割、变化检测 |
| 方法词 | 找到技术路线 | SfM、MVS、Transformer、扩散模型、弱监督、域适应、图优化 |
| 数据词 | 找到可比实验 | 数据集名、传感器、分辨率、场景（输电通道/城市/山地） |
| 应用词 | 找到领域工作 | 电力巡检、无人机遥感、实景三维、应急测绘 |

每组至少准备 3 个同义词/缩写，中英文各一套。检索式用"任务 + 方法 + 数据/应用"组合，不要只搜一个词。

## 二、三轮检索

### 第一轮：领域扫描（建立地图）

- `<task> survey`、`<task> review`、`<task> benchmark`、`<task> 综述`、`<task> 研究进展`。
- 目标：找到 2-3 篇近 3-5 年的综述或基准论文，弄清主流路线、常用数据集、公开挑战。
- 记录：综述覆盖的时间范围、它认为的开放问题（这往往是选题富矿）。

### 第二轮：最近邻（找直接对手）

- `<task> <method> <dataset>`、`<application> <task> deep learning`、`<task> 2024 2025`。
- 每个候选方向找 3-5 篇"如果审稿人会拿来对比"的工作。
- 优先找：同任务不同方法、同方法不同任务、同场景不同数据、同数据不同指标。

### 第三轮：查新（判断是否已被做过）

- 用拟议方法的核心组合做精确检索（加引号）。
- 检索近 6-12 个月的 arXiv（cs.CV / cs.RO / eess.IV）和领域顶会/顶刊。
- 查"citing papers"：找到最接近的一篇，看谁引用了它、有没有人已经做了你的改进。
- 查负面结果：`<method> failure`、`<task> challenge`、`limitations`，避免重复踩坑。

**结论写法**：找不到直接工作只能写"据检索未见"，不能写"首次"。真正的"首次"需要穷尽检索 + 明确检索范围，成本很高，论文中也不宜轻易使用。

## 三、来源分级

| 级别 | 来源 | 用途 | 注意 |
|---|---|---|---|
| A | 同行评审期刊/会议、官方标准、数据集官方页面、官方基准榜单 | 支撑 SOTA、数据集、方法对比 | 仍要核对版本与指标口径 |
| B | arXiv 预印本、技术报告、学位论文、工作组白皮书 | 前沿方法、尚未正式发表的工作 | 必须标注"预印本"，不能当已发表结论 |
| C | 厂商博客、新闻、百科、非官方教程 | 只用于工程事实/产品能力 | 不能支撑学术新颖性或 SOTA |

SOTA 数字至少要有 A 级来源；只有 B 级时写"预印本报告"，并降低确定性。C 级来源不得进入"最近工作表"的核心证据。

## 四、每条证据要记录什么

| 字段 | 说明 |
|---|---|
| 编号 | S1、S2……全文统一 |
| 题名 | 与原文完全一致，不缩写、不改写 |
| 作者 | 前 3 位 + et al. |
| venue | 期刊/会议全称或标准缩写；预印本写 arXiv |
| 年份 | 正式发表年；预印本写首次上传年 |
| DOI/URL | 可访问的稳定链接；记录访问日期 |
| 任务/数据 | 用了什么数据、什么划分、什么指标 |
| 方法要点 | 1-2 句，说明它怎么解决问题 |
| 局限 | 作者承认的 + 你判断的，分开写 |
| 与本研究关系 | baseline / 组件 / 对照 / 数据集 / 仅背景 |
| 证据级别 | A/B/C + 已核实/仅摘要/未核实 |

## 五、核实清单（逐项打勾）

- [ ] 题名、作者、venue、年份与官方页面一致（不是搜索摘要里的二手信息）。
- [ ] DOI 可解析，或 arXiv ID 可打开。
- [ ] 预印本是否已正式发表？若已发表，引用正式版本。
- [ ] 数据集：官方页面可访问，规模、标注类型、许可、划分与论文描述一致。
- [ ] SOTA：同一数据集、同一划分、同一指标；没有跨数据集拼数字。
- [ ] 指标口径：mAP 的 IoU 阈值、IoU 的类别范围、RMSE 的单位与参考面。
- [ ] 代码/模型是否开源；不开源会影响复现与 baseline 选择。
- [ ] 论文是否已被后续工作指出问题（尤其 benchmark 泄漏、标注错误）。
- [ ] 中文文献：若只能看到摘要，标注"仅摘要"，不要据此写具体方法细节。

## 六、常见陷阱

1. **编造引用**：标题、作者、年份、DOI 看起来合理但不存在。任何一条没打开过官方页面，就不能标"已核实"。
2. **把预印本当已发表**：写"arXiv 预印本"而不是"某顶会论文"。
3. **venue 写错**：会议/期刊混淆、年份写成上传年、workshop 写成主会。
4. **数据集版本混淆**：V1/V2、不同划分、不同标注粒度，指标不可比。
5. **跨数据集比 SOTA**：A 数据集 85%、B 数据集 90%，不能直接说谁更好。
6. **指标口径不同**：准确率是 accuracy 还是 precision；召回率在哪类目标上统计。
7. **忽略负结果**：只引用支持自己 idea 的论文，回避失败案例。
8. **拿报告指标当 SOTA**：可研报告的 85%/80% 是项目考核目标，不是文献最高水平。
9. ** predatory 期刊/会议**：来源可疑、审稿周期异常、收费模糊的 venue 不作为 A 级证据。
10. **搜索摘要当全文**：摘要可能省略关键限制；关键结论要打开原文或至少官方摘要页。

## 七、查新结论的写法

对每个 idea 给三档之一：

- **有直接先例**：已有人做过同样的问题+方法+数据。→ 降级或改写（换问题、换约束、换评测）。
- **有相邻工作**：问题相同方法不同，或方法相同场景不同。→ 写清差异维度，作为 contribution 的一部分。
- **据检索未见**：未找到直接工作。→ 仍需说明检索范围与时间，不能宣称"首次"。

差异维度优先选：问题设定、数据条件（稀缺/跨域/多传感器）、约束（算力/实时/隐私）、评测协议、失败模式分析。仅"换一个 backbone/损失函数"通常不足以构成论文贡献。

## 八、证据审计的输出

在最终答复中单列一节，至少包含：

1. **已核实证据表**：编号、题名、venue/年份、DOI/URL、支撑什么结论。
2. **未核实清单**：哪些数字/说法没有找到原始来源，对应 idea 如何降级。
3. **冲突证据**：结论相反或指标不可比的工作，并列说明，不强行统一。
4. **检索边界**：检索了哪些库/时间段/语言，哪些没检索到（如付费墙、非英文文献）。

## 九、引用格式

英文：

```
[S1] A. Author, B. Author, C. Author, et al. Title of the paper. Venue, Year. DOI: 10.xxxx/xxxxx. Accessed YYYY-MM-DD.
```

中文：

```
[S2] 作者1, 作者2, 作者3, 等. 论文标题. 期刊名, 年, 卷(期): 起止页. DOI: 10.xxxx/xxxxx. 访问日期 YYYY-MM-DD.
```

预印本：

```
[S3] A. Author, et al. Title. arXiv:XXXX.XXXXX, Year. Accessed YYYY-MM-DD.
```

正文引用只写 `[S1]`，不要在每个句子后重复完整信息；表格里可以简写为"作者 et al., venue year"。

## 十、检索失败时怎么办

- 网络不可用：明确说明"本次未能联网核实"，把所有新颖性结论标为"待核实"，并降低评分中的新颖性/可辩护性。
- 付费墙：用官方摘要页、作者主页、arXiv 版本交叉核对；仍看不到全文就标"仅摘要"。
- 中文库不可达：用公开摘要、期刊官网、引用该文的综述间接核实；不要凭标题推断方法。
- 数据集页面失效：找镜像或论文附录，标注"官方页面不可访问"，不要假设数据仍可下载。
