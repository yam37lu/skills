# 选题设计：从缺口到可验证的论文

## 一、先找缺口，再想方法

论文选题的起点不是"我想用什么模型"，而是"现有做法在什么条件下不够好"。六类缺口：

| 缺口 | 表现 | 论文可以做什么 |
|---|---|---|
| 性能缺口 | 精度/召回/效率不够，且有明确失败场景 | 新机制、新约束、新训练策略 |
| 鲁棒性缺口 | 跨场景、跨传感器、遮挡、小目标、长尾下掉点严重 | 域适应、几何/物理先验、不确定性建模 |
| 数据缺口 | 标注贵、样本稀缺、类别不平衡、无真值 | 弱/半/自监督、合成数据、主动学习、自建基准 |
| 评测缺口 | 指标不反映业务、缺基线、缺失败分析 | 新评测协议、诊断基准、实证研究 |
| 部署缺口 | 模型大、时延高、显存不够、链路不稳定 | 轻量化、蒸馏、流式/分块、端云协同 |
| 理论缺口 | 为什么有效说不清、边界条件不明 | 误差传播分析、可辨识性、泛化界 |

缺口必须能被证据支撑：引用失败案例、报告里的现场问题、公开 benchmark 的短板。不要用"具有重要意义"代替缺口。

## 二、选题原型（挑一个，不要混着写）

| 原型 | 核心 contribution | 审稿人最看重 | 主要风险 |
|---|---|---|---|
| 新任务/新问题 | 提出一个此前未被形式化的问题 | 问题是否真实、定义是否清晰、基线是否合理 | 被说"伪需求" |
| 新方法/新模块 | 新机制带来可解释的提升 | 与强 baseline 的公平对比、消融充分 | 模块堆叠、增量 |
| 新数据集/基准 | 数据规模、多样性、标注质量、评测协议 | 数据卡、许可、基线、难度分析 | 标注成本、隐私 |
| 新评测/实证分析 | 揭示现有评测的偏差或方法的边界 | 洞察是否新、实验是否系统 | 被说"只是调参" |
| 跨域/迁移 | 解决源域到目标域的落差 | 域差距分析、目标域收益 | 只换数据集 |
| 系统/应用 | 端到端系统在真实场景的验证 | 部署证据、工程指标、可复现 | 创新性不足，需配方法贡献 |
| 效率/边缘 | 在精度约束下显著降本 | 延迟/显存/能耗的硬指标 | 只做剪枝量化 |
| 不确定性/质量 | 让模型知道"自己不知道" | 校准指标、与决策的关联 | 指标好看但无应用 |

一篇论文只选一个主原型；其他贡献作为支撑。混合三个以上原型通常意味着故事没讲清。

## 三、从方向到选题：四个要素

一个可执行的选题至少写清：

1. **任务**：输入什么、输出什么、成功标准是什么。
2. **数据**：公开数据集或自建数据；规模、标注、划分、许可。
3. **方法切入点**：针对哪个缺口，改哪一环，为什么这一环是关键。
4. **评价方式**：主指标、baseline、消融、鲁棒性、效率。

缺任何一项，选题还停留在"方向"层面，不能进入深化。

## 四、创新点的写法

每个创新点写成四元组：

```
主张：我们提出/发现……
机制：它为什么能解决问题（因果链，不是"因为加了注意力"）
证据：哪个实验/消融/分析能证明
边界：在什么条件下不成立
```

合格：

- "我们发现分块独立平差是接边误差累积的主因，提出跨块全局约束，使接边平面误差在 X 数据集上从 A 降到 B；去掉约束后回退到 A。"

不合格：

- "提出了一种多尺度注意力融合框架，提升了特征表达能力。"（没有机制、没有对照、无法证伪）

创新类型按强度排序：

1. 新问题/新任务定义；
2. 新机制（有因果解释）；
3. 新数据/基准（有社区价值）；
4. 新评测/实证洞察；
5. 新组合（必须证明组合后的交互效应，否则最弱）。

"首次"只在穷尽检索后使用；否则写"据检索未见"。

## 五、技术路线模板

```
问题形式化
  → 数据与预处理
  → 强 baseline 复现
  → 模块 A（创新 1）
  → 模块 B（创新 2）
  → 联合训练/推理
  → 主实验
  → 消融（每个创新一组）
  → 鲁棒性/效率/跨域
  → 失败分析与结论
```

每一段都要能回答：

- 输入/输出是什么？维度、坐标系、分辨率、单位。
- 为什么需要这一步？去掉会怎样？
- 计算代价多少？训练/推理时间、显存。
- 失败模式是什么？在哪些样本上会错？
- 与 baseline 的差异是否只有这一处？

## 六、实验设计清单

| 项目 | 最低要求 | 常见扣分点 |
|---|---|---|
| 数据划分 | 场景级划分，避免同区域泄漏；跨区域测试 | 随机切图导致泄漏 |
| Baselines | ≥2 个强 baseline + 项目现有做法 | 只对比过时方法 |
| 主指标 | 任务标准指标 + 业务相关指标 | 只报最好看的指标 |
| 消融 | 每个创新一组；模块移除/替换/顺序 | 只做整体消融 |
| 鲁棒性 | 跨季节/传感器/分辨率/遮挡/噪声 | 只在同一分布测试 |
| 效率 | 参数量、FLOPs、时延、显存 | 回避部署成本 |
| 统计 | 多 seed、均值方差、显著性 | 单次运行 |
| 定性 | 成功/失败案例各若干 | 只放成功图 |
| 复现 | 代码、配置、数据版本 | 缺超参 |

## 七、最小可发表单元（MPU）

先定义 MPU，再决定做多少模块：

- **Letter/Workshop**：1 个主实验 + 2 组消融 + 1 个失败分析。
- **领域期刊**：2 个数据集 + 3-4 个 baseline + 每个创新一组消融 + 鲁棒性/效率。
- **顶会**：新问题或新机制 + 强 baseline + 充分消融 + 分析洞察；仅有应用场景通常不够。

6-12 个月的项目，建议 1 个主创新 + 1 个辅助创新；超过 3 个模块通常做不完，也不容易讲清。

## 八、领域视角（示例，不是事实断言）

以下是无人机遥感/摄影测量/电力巡检类课题常见的缺口来源，用来启发检索方向；具体是否有空白，必须查文献确认。

| 子领域 | 可查的缺口 |
|---|---|
| 三维重建/摄影测量 | 大场景分块平差的全局一致性、弱纹理/重复纹理匹配、跨传感器配准、真正射遮挡检测、重建质量的不确定性评估 |
| 点云处理 | 语义/实例分割、LOD 与流式传输、压缩、配准、点云变化检测、轻量化部署 |
| 遥感影像理解 | 小目标、遮挡、长尾、域适应、弱/半监督、开放词汇/多模态、矢量多边形化、评测偏差 |
| 电力巡检 | 树障与安全距离、绝缘子/金具缺陷、缺陷样本稀缺、跨无人机平台泛化、边缘实时推理、三维量测 |
| 系统与工程 | 端到端流程优化、数据版本与质量门控、人机协同标注、可复现基准、生产级评测 |

使用方式：先选 1-2 个子领域，再用"缺口类型 × 选题原型"组合，最后查最近工作验证。

## 九、弱选题 vs 强选题

弱：

- "基于深度学习的无人机影像地物提取研究。"——没有条件、没有缺口、没有对照。
- "把 A 模块和 B 模块结合，提升性能。"——组合不是贡献。
- "构建一个平台。"——工程交付，不是论文问题。

强：

- "遮挡与长尾条件下的电力部件检测：几何先验与不确定性校准。"——有条件、有机制、有指标。
- "大场景分块重建的接边误差传播分析与全局约束。"——有诊断、有因果、有可验证的改进。
- "跨无人机平台的影像域适应：以未标注目标域数据降低重训成本。"——有域差距、有数据策略。

## 十、审稿人最常提的反对意见（提前准备）

1. 增量：与最近工作差异太小。→ 在 gap 表里逐条对比，差异落到问题/约束/评测。
2. baseline 不公平：用了更强的主干或更多数据。→ 控制变量，补充同 backbone 对照。
3. 数据泄漏：同一区域/同一航线跨 train/test。→ 场景级划分，跨区域测试。
4. 只在自建数据有效：缺公开基准。→ 至少一个公开数据集 + 一个自建数据。
5. 模块堆叠：每个模块都涨一点，但说不清为什么。→ 消融 + 机制分析 + 失败模式。
6. 无部署验证：效率、时延、稳定性缺失。→ 加效率表与真实/仿真部署。
7. 不可复现：代码/配置/数据版本缺失。→ 复现包。
8. 伦理与合规：航拍影像涉隐私/敏感设施。→ 脱敏、许可、伦理声明。

## 十一、组合与节奏

- 稳妥 idea：数据现成、方法成熟、MPU 短，用来保底。
- 冲刺 idea：问题新、上限高，但依赖关键数据或算力。
- 快速 idea：workshop/short paper，3 个月内可完成。
- 三个 idea 不要共用同一个瓶颈（同一批数据、同一个算力、同一个标注团队）；否则一个卡住全盘停。
- 先做能验证核心假设的最小实验，再决定是否投入完整实验矩阵。
