# 讲解输出模板

默认按下面的顺序写。报告没有的内容跳过，不要留空标题；用户指定"按课题讲"时，以课题为主干，把背景压缩到半页。

篇幅基准：完整版 2000-4000 字；"简短版"500-800 字加技术总表；单课题深入版 800-1200 字。

## 0. 开头：一句话 + 阅读地图

```
这份报告研究的是一件事：<用一句不含术语的话说清项目要做什么、为谁解决什么问题>。

它由 <N> 个课题组成：
1. <课题名>——<一句话作用>
2. ……

读完后你应该能回答：<与项目最相关的 3 个问题>。
```

3-5 行即可，不要写成摘要式罗列，也不要先铺陈"随着……的发展"。

## 1. 项目背景：为什么非做不可

按"三层递进"写，每层一段：

1. **行业/业务变化**：什么趋势让这件事变重要。引用报告里的具体场景（如"输电线路巡检、工程验收、灾害勘察"），不要只写宏观口号。
2. **现有做法与瓶颈**：现在靠什么做、卡在哪。把报告里的失败现象写成具体画面（例如"大场景分块重建失败、模型扭曲接边错位"），并说明原因属于数据、算法还是工程链路的哪一环。
3. **不做的后果**：数据越积越多但用不起来、时效跟不上、成本或风险如何。

最后用 2-3 句收束成"研究需求"：所以要研究 A、B、C，分别对应哪类瓶颈。

> 写法提示：背景不是政策复述。每条政策/趋势后面都要接"因此业务上出现了什么新需求"。

## 2. 项目总体在做什么

- **总体目标**：一句话，含对象、能力、边界。
- **研究主线**：2-4 条，对应课题；每条用"从 X 到 Y"的句式（从"人工拼接"到"自动化重建"）。
- **最终交付物**：算法/引擎、原型系统、技术报告、专利/软著/论文（只列学术与交付物，不列经费和市场收入）。
- **文字版结构图**：用数据流说明课题关系，例如：

```
多源航拍影像、点云
        │
        ▼
课题 1  三维重建与正射影像  ──►  三维模型 / DOM / DEM
        │
        ▼
课题 2  地物要素提取与点云轻量化  ──►  要素矢量 / 3D Tiles 服务
        │
        ▼
课题 3  自动化生产原型系统与试点  ──►  可运行的生产系统
```

箭头表示数据依赖，不表示时间顺序；按报告实际逻辑画，不要生搬。

## 3. 课题逐一讲解（主体）

每个课题用同一模板，标题保留报告原名（如"课题二：航拍数据地物要素智能提取与点云高效处理技术研究"）。

### 课题 X：<报告中的课题名>

**一句话**：<这个课题要让什么从"不能"变成"能"；一句话，不超过 40 字>。

**要解决的问题**

- 场景：<在什么业务场景下发生>
- 现状：<现在怎么做，依赖什么>
- 卡点：<技术难点 2-4 条，尽量引用报告描述的现象；每条说明"难在哪"而不是"很重要">

**研究内容**

分 3-6 条写"做什么"，每条以动词开头（研究/构建/设计/实现/验证）。不要把"意义""必要性"混进来，也不要只抄课题名。

**技术路线**

用编号步骤写清输入→处理→输出；能画流程就画 3-5 行文字流程：

1. 输入：<数据、前提、约束>
2. 步骤一：<方法名>，解决<子问题>
3. 步骤二：……
4. 输出：<成果形式与指标>

如果报告只给了方法名、没给步骤，按"输入—方法—输出"补全到能读懂为止，并注明"步骤按报告描述整理"。

**关键技术**

2-5 项，表格呈现：

| 技术 | 通俗解释（一句话） | 在本课题中干什么 | 难点 / 为什么不是现成能用 |
|---|---|---|---|
| SfM | 用很多张照片反推"拍照时站在哪、朝哪看" | 把无序影像对齐到统一坐标系 | 大场景误差累积、分块接边 |
| … | | | |

**预期成果与指标**

- 成果：<算法/系统/报告，对应报告"成果形式">
- 指标：<报告原文数字>；用一句话解释这个指标测的是什么、大概什么水平。
- 若报告只有"提升效率"这类定性说法，写"报告未给量化口径"，不要自己编数字。

**与其他课题的关系**

- 上游依赖：<需要谁提供什么数据/能力>
- 下游支撑：<给谁提供什么>
- 边界：<这个课题不做什么，避免与相邻课题重复>

> 若报告没写课题关系，根据数据流补一句"按报告的数据流向推断"，不要说得像原文。

## 4. 技术总表（跨课题）

| 技术/缩写 | 全称 | 一句话它是干什么的 | 用在哪 | 关键作用 |
|---|---|---|---|---|
| SfM | Structure from Motion，运动恢复结构 | 从多视角照片反推相机位置和场景三维结构 | 课题 1 | 三维重建的第一步 |
| … | | | | |

10-20 行为宜，按课题顺序或技术族排序。正文已解释过的缩写在这里只做速查，不重复长篇解释。

## 5. 技术展开：挑 2-4 个"卡脖子"技术讲透

选择标准：报告着墨最多、指标最硬、或读者最陌生的技术。每个 300-500 字，按四段写：

1. **是什么**：一句人话 + 一个类比（类比后补边界）。
2. **为什么难**：不用它会遇到什么，报告里的失败现象如何对应。
3. **报告怎么做**：技术路线的关键 2-3 步，说清输入、关键动作、输出；不推导公式。
4. **做完能怎样**：对应哪条指标、哪个课题成果。

## 6. 一页纸总结（给没时间的人）

- 项目一句话：……
- 三个课题各一句：……
- 三个关键词（技术层面）：……
- 三个数字（指标）：……（每个数字后括号说明它测什么）
- 一句话说明"做成后最大的变化"：……

## 7. 术语表（可选）

| 术语 | 全称/英文 | 一句话解释 | 首次出现 |
|---|---|---|---|

只在术语超过 8 个、或用户明确要求时给。正文已经解释清楚的词不必重复收录。

## 8. 报告没讲清的地方（可选，只限学术口径）

只列影响理解的技术缺口，每条附一句"对结论的影响"。例如：

- "分块重建的接边误差如何度量、阈值是多少，报告未说明——因此'无缝拼接'目前只是目标，不是可验收的指标。"
- "地物识别只给了准确率和召回率，没有给测试集规模和类别分布——指标的可比性有限。"

不要列人员、经费、进度、组织管理方面的问题；用户明确要求评审这些内容时，另行说明超出本 skill 的范围。

## 附：不同场景的裁剪

- **用户只要"讲讲这个项目"**：0 + 1 + 2 + 3（每课题压缩到"一句话 + 研究内容 3 条 + 2 个技术"）+ 6。
- **用户是同行，想快速判断水平**：1 压缩，3 保留"技术路线 + 关键技术 + 指标口径"，5 加深，8 必给。
- **用户是领导/业务方**：1 和 2 展开场景，3 只留"一句话 + 解决什么 + 产出"，技术总表保留，5 只讲 1-2 个。
- **报告分多个课题且篇幅很长**：先出"总览 + 讲解目录"，让用户点选，再逐题输出。
