# 讲解手法与常见技术族

## 一、一个技术讲四层

1. **它是什么**：一句人话，加一个类比。
2. **为什么需要**：没有它，报告里的哪个痛点解决不了。
3. **它怎么做**：最多 3 步，说清输入、关键动作、输出；不展开公式和网络结构。
4. **它在本项目的位置**：属于哪个课题、上下游是谁、对应哪条指标或哪项成果。

四层不必都成段出现。技术总表里可以只占一格；被选为"关键技术"展开时才写全。

## 二、类比库（用完补边界）

| 技术族 | 类比 | 必须补的边界 |
|---|---|---|
| 三维重建 / SfM | 根据几百张不同角度的照片，反推每张照片"站在哪、朝哪拍"，再把场景搭出来 | 不是照片拼接；核心是特征匹配和光束法平差，误差会累积 |
| MVS / 密集匹配 | 知道相机位置后，逐像素找同一点在不同照片中的位置，像几十只眼睛同时测距 | 依赖纹理；反光、弱纹理、重复纹理容易失败 |
| 空中三角测量 | 把大量影像连成一张网，统一到一个大地坐标系 | 大场景要分块平差，接边处最考验稳定性 |
| 正射影像（DOM） | 把有透视的航拍照片"压平"成正上方看的地图 | 只是几何纠正，不是三维；高地物会有投影差 |
| 真正射（true ortho） | 用三维模型判断哪里被遮挡，把被楼顶"拉歪"的地面补回来 | 依赖模型精度和遮挡检测；补出来的区域是推算值 |
| 点云 | 空间中一大堆带坐标的点，密到一定程度能看出物体形状 | 不是照片，没有颜色纹理时判读困难；数据量极大 |
| 3D Tiles / LOD | 把巨大三维场景切成瓦片，近处给细的、远处给粗的，像地图分级缩放 | 瓦片划分和 LOD 切换策略决定流畅度；不是压缩算法本身 |
| 目标检测 | 给模型看大量标注样本，学会"看到这种形状就框出来" | 只给框，不给像素边界；小目标、遮挡、域偏移是主要难点 |
| 语义分割 | 给每个像素分类，标出这是路、这是树、这是建筑 | 边界细但不区分个体；标注成本高 |
| 多源融合 | 把影像、点云、卫星图等不同"尺子"的数据对齐到同一坐标和精度体系 | 关键在配准和误差传播，不是简单叠加 |
| 数字孪生 / 实景三维 | 把真实世界按地理位置建成可量测、可分析的三维模型 | 强调地理精度和可量测性，不是游戏场景 |
| 微服务 / 容器化 | 把大系统拆成一组能独立部署的小服务，像把整机拆成标准零件 | 带来运维和网络开销；不是所有系统都适合拆 |
| 边缘计算 | 把计算放到离数据近的地方，少传原始数据 | 受算力和功耗限制；模型要轻量化 |
| 大模型 / 多模态 | 用海量数据预训练的通用模型，通过提示或微调完成多种任务 | 报告若只写"引入大模型"而无用法，标注"报告未说明具体机制" |

类比只用于建立第一印象。凡涉及精度、可靠性、适用条件的结论，必须回到报告的技术表述。

## 三、常见错误

1. **拿"意义"当"内容"**：只写"提升效率、支撑转型"，没写具体研究什么。
2. **技术名罗列**：写了 SfM、MVS、3D Tiles，却没说各自解决哪一步。
3. **形容词代替机制**："智能、精准、高效"没有输入输出和判据。
4. **类比过度**：把三维重建说成"拼图"却不提几何约束，让读者低估难度。
5. **指标无参照**："准确率 85%"要解释成"100 个目标里约 85 个认对"，并说明漏检和误检各自的代价；若报告未说明是 precision 还是 accuracy，点出这个口径问题。
6. **把预期当既成**：报告写"将实现"，讲解不能写成"已经实现"。
7. **课题串味**：把课题 2 的算法写进课题 1。先画数据流再动笔。
8. **管理内容抢戏**：花篇幅评价经费、进度、人员；与理解学术内容无关。
9. **照抄目录**：把报告小标题原样搬一遍，没有解释。
10. **过度补充**：凭常识给报告加上"采用了 Transformer/大模型"等未出现的细节。
11. **平均用力**：每个课题一样长，读者抓不住重点。至少有一个课题讲到技术机制层。
12. **忽略"现状"**：只讲项目要做什么，不讲别人已经做到什么水平，读者无法判断创新点。

## 四、按读者调整

| 读者 | 背景 | 技术 | 指标 | 篇幅 |
|---|---|---|---|---|
| 业务负责人 / 领导 | 展开场景与"不做会怎样" | 只讲 1-2 个关键技术的类比 | 只留 3 个，配参照物 | 800-1500 字 |
| 产品经理 / 项目经理 | 讲清业务链路和数据流 | 讲每个技术"负责哪一步" | 讲指标对应哪个功能 | 1500-2500 字 |
| 新入职技术同事 | 简写 | 四层法讲透，补领域常识 | 解释口径和测试方法 | 2500-4000 字 |
| 同行专家 | 一笔带过 | 讲机制、对比、局限 | 追问口径、数据集、基线 | 按需，可只给 3、5、8 节 |

## 五、讲解节奏

- **总—分—总**：开头 5 行总览，中间按课题展开，结尾一页纸。
- **每课题 500-900 字**；技术总表控制在 1 页内。
- 长报告先给"讲解目录"，让用户点选深入；不要一次输出一万字。
- 每讲完一个课题，用一句话回扣总体目标，避免读者迷失在细节里。
- 数字只留最有信息量的：精度、召回率、效率提升、覆盖范围；同一指标不要在全文重复三遍。
